# 履约问题诊断与运营优化优先级

## 核心业务决策

当运营团队只能跟进少数商家时，应该先排查哪些商家的哪些履约环节，才能在给定改善幅度下覆盖最多延误订单？

固定默认口径及敏感性对照。正式分析从样本覆盖和分母出发，保留效应较弱或不稳定的结果，并记录样本变化及判断依据。

## 四个分析模块

| 模块 | 数据与指标 | 方法与输出 | 完成标准与缺失策略 |
| --- | --- | --- | --- |
| A. 履约诊断 | 订单 ID、状态、客户州、订单品类、下单、交接、签收、预计时间。度量订单量、已交付比例、可判率、延误率、延误量、日差和两段时长 | DuckDB 按下单月、州和品类聚合。Python / Matplotlib 展示月度量率、州和品类量率对照、同样本阶段 P50 / P90。用延误量确定排查规模 | 平台指标与原始订单表核对，区分交付状态与延误资格。每张图附分母。缺时间只影响对应时长或资格，分组显示覆盖。多品类主图可用互斥主品类，触达附表保留所有分类。小分层只展示量或合并标识 |
| B. 低评分关联 | 订单 ID、跨订单客户 ID、延误标识和日差、评分、评价数量与时间、目的州、主品类、下单月、商家 ID。度量有评覆盖、1–5 分分布、分段低评率、风险差和 OR | SQL 分组后用 SciPy 做 χ²、OR 与区间。正式阶段拟合二项 Logit，分别报告粗模型与含月、州、品类的调整模型，单卖家样本按商家聚类。检查重复客户、窄窗口、低评分阈值和不同评价选择规则。输出覆盖表、评分分布、置信区间图及回归表 | 明示所有组的样本量、效应和不确定性，报告极端月与聚类稳健性结果。缺评分保持为空并按延误状态比较覆盖。稀疏类别合并。若调整模型分离或不收敛，汇报可复现的描述性分层及粗模型 |
| C. 商家优先级 | 订单—商家组合、单卖家标记、可判标记、延误、目的州、主品类、下单月和商家州。度量候选样本量、平滑延误率、延误集中度、超额延误量及同层覆盖 | SQL 默认样本门槛 50，比较 30 / 100 的候选覆盖及排名变化。用 50 笔基准权重平滑，按超额延误量排序。同目的州 × 主品类留一商家对照。按下单时间分早期排序和后期复核。输出集中曲线、候选表及阶段排查标签 | 给出候选与覆盖，解释不稳定名次。检验样本门槛、分层覆盖及跨期稳定性。多卖家交易单列为履约链路排查入口。稀疏分层只评估有足够同行订单的部分，并披露剩余份额 |
| D. 改善情景 | 去重候选、样本内延误数、可判订单量、评价覆盖和低评风险差。度量改善后延误率、预计减少延误数与可选低评记录情景 | 以可用运营名额选候选，计算 10% / 20% 相对改善以及分组上下界。显示假设、候选基线、情景表和目标商家范围敏感性 | 每个结果可从候选级别重算。订单量固定，评价扩展假设须独立披露。若低评关联跨期不稳或覆盖差异过大，仅给延误量和低评变化区间，或省略低评推算 |

## 最终 Dashboard 页面设计

1. **平台与流程**。订单量、已交付比例、可判率与延误率，配分时趋势、目的州和品类量率图及两阶段时长。支持下单月、州和品类筛选，卡片和图表展示资格分母。
2. **客户评价**。延误分组评分分布、低评风险差及延误天数分段图，配评价覆盖、阈值和观察窗口说明。
3. **商家优先级**。候选覆盖、集中度和可排序表，展示原始率、平滑率、超额延误与同层覆盖。钻取到目的州、主品类和可用阶段数据。
4. **情景估算**。候选名额与改善幅度控件，展示减少延误订单的期望数，及启用低评情景时使用的评价覆盖和风险差。

## 最终报告章节

1. 运营决策与适用范围。
2. 数据关系、质量和指标口径。
3. 平台延误及区域、品类和阶段诊断。
4. 履约延误与低评关联、覆盖和稳健性。
5. 商家优先名单、同层对照和建议排查环节。
6. 改善情景与运营容量约束。
7. 局限、验证方法与附录。
