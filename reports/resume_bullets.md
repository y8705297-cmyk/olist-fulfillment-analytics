# 电商平台履约诊断与运营优先级分析

**技术栈**　SQL / DuckDB、Python / Pandas、SciPy / Statsmodels、Matplotlib、Streamlit

- 基于 Olist Kaggle v2（下单日期 2016-09-04 至 2018-10-17）的九张业务表，构建 99,441 行订单事实表及 100,010 行订单—商家事实表，处理商品、支付、评价的一对多关系，完成 15 项口径与对账测试。
- 对 96,470 笔可判订单诊断履约异常，识别 6,534 笔延误（6.77%）及 2017-11、2018-02、2018-03 三个高峰。使用 Logistic 回归控制下单月、目的州与主品类，延误组和按期组低评率为 62.42% 与 9.27%，调整 OR 为 15.44。
- 以双期各 ≥50 笔可判单卖家订单为样本门槛，要求两期平滑超额延误为正，后期目的州 × 主品类同行覆盖 ≥70% 且实际延误高于同行期望，筛出 21 家高峰期回顾性排查对象。该群在 2018 年 2–3 月有 366/1,522 笔延误，延误率相对下降 10% / 20% 的情景分别估算减少 36.6 / 73.2 笔。
- 开发五页 Streamlit Dashboard，经营概览和履约诊断支持下单月份、目的州与主品类筛选。客户体验和商家优先级页标注固定分析样本，改善情景页在固定商家群体上独立调节相对降幅，为线路排查和试点规划提供依据。
